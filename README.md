# BiliBox

把 B 站上想留住的视频，批量存进自己的硬盘。

本地网页界面，Windows 免安装，解压双击就能用。没有任何命令行操作，也没有账号密码上传——所有请求都在你自己的电脑上完成。

---

## 它解决什么问题

B 站官方客户端只能缓存，不能导出；网页端也没有批量下载。而真实的需求往往是一整个收藏夹几十上百条视频、几十 GB——想存到本地慢慢看、转成音频、装进平板、做二次剪辑。

市面上能用的工具大多只做单条：粘一条链接存一条，遇到收藏夹就断了。能批量下六七十条的浏览器插件基本会挂，剩下的多数要装 Python 环境、敲命令行。

BiliBox 针对这个缺口做的三件事：

**六种链接全支持批量。** 单视频、多分 P、UP 主投稿、合集/系列、收藏夹、番剧——贴一个链接进去，解析出来的是一份可勾选的清单，不是孤零零一条。尤其是 **UP 主投稿** 和 **收藏夹** 这两个类型，目前市面上大部分工具做不到一次性全量下载：贴一个 253 条的收藏夹，全部条目一次列出，勾选后批量跑完，速度按实测在大文件单线程 22.24 MB/s、8 线程 25.41 MB/s 的量级。

**断了能接着下。** 下到一半关程序、断网、电脑休眠，重开后任务标成「已中断」，点「继续下载」只补没下完的部分。实测 13MB 视频下到 6/7 片时强杀进程，重开 4.8 秒补完。

**收藏夹更新只下新的。** 解析完，下过的条目带「已下载」角标且默认不勾选；点「只选新增」自动只勾没下过的。

## 功能清单

| 能力 | 说明 |
| --- | --- |
| 链接类型 | 单视频、多分 P、UP 主投稿、合集/系列、收藏夹、番剧 |
| 画质 | 最高 8K（登录后），未登录封顶 720P |
| 音频 | 可只下音频（m4a），音质可选 64K / 132K / 192K / 杜比 / Hi-Res |
| 附加文件 | 封面、字幕（srt）、弹幕（转 ass） |
| 登录 | B 站扫码登录，不保存密码 |
| 文件整理 | 平铺 / 每条一个文件夹 / 按类型分目录，三档可选 |
| 下载目录 | 可自选任意本地目录 |
| 任务管理 | 分组折叠、单条取消、失败重试、明细展开 |
| 断点续传 | 分片缓存 + 重启恢复 |
| 任务持久化 | 关程序不丢历史 |
| 增量下载 | 已下载标记 + 只选新增 |

## 快速开始（Windows）

1. 下载 Releases 里的 `BiliBox-win64-v2.0.zip`
2. 解压到任意目录（路径里不要有空格和中文更稳）
3. 双击 `启动 BiliBox.bat`
4. 浏览器会自动打开 `http://127.0.0.1:8931`（端口被占会自动顺延，看窗口里的提示）

首次使用建议先点右上角「未登录」扫码登录，否则画质会被限制在 720P。

不需要安装 Python，不需要安装 ffmpeg，全部打包在 `runtime/` 里。

## 项目结构

```
BiliBox/
├── app.py            HTTP 服务、任务调度、全部 API 路由
├── biliapi.py        B 站客户端：wbi 签名、指纹、取流、收藏夹/合集解析
├── downloader.py     下载核心：分片、断点、合并、字幕/弹幕转换
├── records.py        下载记录与续传缓存管理
├── config.py         配置读写
├── web/              前端（原生 HTML/CSS/JS，零构建）
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   └── qrcode.min.js
├── data/             运行时生成：下载记录、任务历史、续传缓存
└── downloads/        默认下载目录
```

## 技术要点

**后端只用标准库。** `ThreadingHTTPServer` 起服务，`urllib` 发请求，没有 Flask / FastAPI 之类的依赖，所以能塞进 11MB 的 Python 嵌入包。

**前端零构建。** 原生 JS，没有 React / Vue / 打包工具，改一行刷新就生效。

**自研 B 站客户端。** wbi 签名、`buvid3` 指纹 Cookie、DASH 取流、`playurl` 多画质重试，全部自己实现，不依赖 yt-dlp（早期试过，机房 IP 直接被 412 拦）。

**分片下载用固定线程池。** 早期版本一片起一个线程，100MB 文件会同时打 17 个请求到 CDN，触发限流和校验失败。现在是固定 8 线程从队列取任务。

**断点续传的实现。** 每个视频一个稳定缓存目录（`md5(bvid|cid)`），分片文件和一份 `parts-video.json`（记录哪些片已完成、每片多大）落盘。重启后读这份记录，跳过已完成的片。片大小对不上就丢弃重下，避免半截文件混进去。

**打包。** Python 用华为云镜像的 `python-3.12.7-embed-amd64.zip`（11MB，含标准库 `python312.zip`）；npmmirror 的同名包缺标准库，直接用会起不来。ffmpeg 用 imageio-ffmpeg 的静态版本。整个包 47.7MB，其中 ffmpeg 占 101MB 压缩后约 40MB。

## 已知限制

- **未登录最高 720P**，部分视频只给 480P。这是 B 站的服务端限制，不是程序问题。
- **浏览器登录 ≠ 程序登录**。`SESSDATA` 是 HttpOnly，程序读不到浏览器 Cookie，只能扫码。
- **云服务器 IP 容易被风控**。在机房 IP 上访问 space/popular 等接口会返回 `-412` / `-799`，家用宽带正常。
- **Windows 实机尚未验证**。分发包的结构和文件完整性都校验过，但没有在真实 Windows 上跑过完整流程。
- **番剧付费内容**需要对应账号有权限，否则取流失败。
