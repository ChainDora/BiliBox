## v2.2 · 换画质重下修复

**修复**

- 同一视频先用 720P 下过、之后再选 4K，第二次会秒完成但实际没下——低画质文件被当成「已下载」
  - 根因：跳过判断只看 `os.path.exists(out_path)`，而路径只由标题拼成，不含画质
  - 新增 `quality_tag()`：把「实际能拿到的画质」压成 `v720_AVC1` 形式的稳定标签，缓存目录 / 跳过判断 / 下载记录三处共用
  - `records.mark()` 增加 `qual` / `qual_text` / `max_h` 三个字段
  - 缓存目录带上画质标签，低画质的残缺分片不会被高画质复用
  - 跳过前比对记录里的 `qual`，不同则重下覆盖，并在日志写明「已有 X，本次要 Y」
  - 老记录没有 `qual` 字段时保持原跳过行为，向后兼容
- 顶栏版本徽标写死 `2.0`，改为从 `/api/status` 回填，消除第二份版本真相源

**变更**

- 前端「已下载」标记跟随当前画质联动：当前画质下不是同一份产物时，显示琥珀色「已下 480P」而不是置灰
- 切换画质时按新画质重算勾选，并提示「N 条之前下的是低画质」
- `/api/parse` 每条新增 `dl_qual` / `dl_qual_text` / `dl_max_h`
- 版本号 `APP_VER` 改为 `2.2`

**实测**

- 360P 产物 14,767,126 字节 / 480P 产物 26,347,806 字节，两次切换各自「重下并覆盖」，第三次同画质才跳过
- `BV1GJ411x7h7` 未登录封顶 480P：请求 720P 与实际 480P 标签相同，跳过正确（判据是实际画质，不是请求档位）

## v2.1 · 番剧时长单位修正

**修复**

- 番剧（pgc）接口返回的 `duration` 单位是**毫秒**，此前当秒直接使用，造成三个连锁问题
  - 列表里每条时长显示成 300~400 小时（一集 25 分钟的番剧）
  - 预估体积虚高 1000 倍（一集显示 58.2GB，实际约 190MB）
  - 进度加权被单集撑满，一条番剧就吃掉整个进度条
- 新增 `_pgc_seconds()`：超过 86400 的值按毫秒折算，其余按秒原样返回，兼容个别返回秒的情况
- 番剧条目名由裸集号（“1”“2”）改为「集号 + 长标题」，146 话的番剧终于能在列表里认出是哪一集

**变更**

- 版本号 `APP_VER` 改为 `2.1`

**实测**

- 宝可梦 太阳&月亮 全三季（ss23795，146 话）：单集 24分28秒，全选 60小时10分 / 27.5GB（未登录 720P 封顶）
- 凡人修仙传（ss28747，317 话）：单集 17.9~20.1 分钟
- 单集预估由 58.2GB 修正为 191MB

## v1.9 · 代码审查

**修复（6 个真实 bug）**

1. 取消过的条目重试永远复活不了 — `_api_retry` 没重置 item 的 `_token`
2. 单流下载失败被当成功 — `_download_single` 返回值未被检查，错误被 ffmpeg 报错掩盖
3. 重试后总进度翻倍 — `rewind()` 未清 `total`
4. 分片线程数失控 — "一片一线程"，100MB 切 17 线程
5. 超长标题写盘失败 — 按字符截断，中文字节超 255
6. 字幕时间戳可能为 1000ms — 浮点取整溢出

**优化**

- 已存在文件跳过（重复下载 3.0s → 0.9s）
- 未登录画质封顶 720P，省 3~4 次无效请求
