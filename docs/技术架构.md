# 技术架构

6 个 Python 文件、4 个前端文件，合计 5422 行。后端零第三方依赖。

## 模块划分

```
浏览器 (原生 JS)
     │  fetch /api/*
     ▼
app.py ──────────────────────────────────────┐
```

## 各模块职责

### app.py（1293 行）

**HTTP 层**：`ThreadingHTTPServer`，路由用前缀匹配。静态文件（`web/`）直接返回，API 走 JSON。

**JobManager**：任务队列。核心是三个字段：

- `jobs`：id → Job 的字典
- `_dirty`：是否有未落盘的变更
- `_saver_loop`：后台线程，每 1.5 秒检查一次 `_dirty`，有变更就写 `data/tasks.json`

任务有 `running / queued / done / cancelled / error / interrupted` 六种状态。启动时从磁盘加载，`running` / `queued` 一律改成 `interrupted`，提示"上次没有下完，点继续接着下"。

**解析层**：`_api_parse` 拿到链接，分派给 `_parse_video` / `_parse_favlist` / `_parse_space` / `_parse_season` 等，输出统一的 `parsed` 结构，再给每个条目附 `downloaded` 标记。

**下载编排**：`_download_one` 是最核心的函数（约 180 行）。流程是：

1. 算 `out_path`，存在且非空 → 跳过
2. 建缓存目录
3. 取播放信息
4. 视频流 + 音频流分别下载（或单流）
5. ffmpeg 合并
6. 写封面 / 字幕 / 弹幕
7. `records.mark` 记录已下载
8. `cache.drop` 清缓存

### biliapi.py（1032 行）

**wbi 签名**：B 站 2023 年后给部分接口加了 wbi 校验。需要对参数按 key 排序、拼 query、再用 `mixin_key` 做 MD5。mixin_key 从 `/x/web-interface/nav` 的 `wbi_img` 里取，24 小时刷新一次。

**指纹 Cookie**：首次请求 `/x/frontend/finger/spi` 拿 `buvid3` / `buvid4`，之后所有请求带上。不带会被判成爬虫。

**取流**：`get_playinfo(bvid, cid, aid, ep_id, qn, audio_only)`

- 普通视频走 `/x/player/wbi/playurl`，参数 `qn` / `fnval=4048` / `fourk=1`
- 番剧走 `/pgc/player/web/playurl`
- 返回 DASH 格式，视频流和音频流分开

**画质降级**：请求的画质拿不到时，从返回的 `accept_quality` 里挑次一档，最多重试 3 次。

**登录**：`passport-login/web/qrcode/generate` 拿二维码，`poll` 轮询状态。成功时响应里的 `data.url` 形如 `https://passport.biligame.com/crossDomain?DedeUserID=...&SESSDATA=...`，从中提取三个 Cookie 值。

### downloader.py（633 行）

**StreamFetcher**：单个流的下载器。

- 先用 Range `bytes=0-1` 探真实总长（`Content-Range` 里的值比 `Content-Length` 可信）
- 总长 < `SINGLE_THRESHOLD`（8MB）或单线程 → 整段下载
- 否则按 `CHUNK_MIN`(2MB) ~ `CHUNK_MAX`(6MB) 切片，固定线程池

**断点续传**：

- 整段：保留 `.tmp`，重开时用 Range 从已有字节续；响应 206 → append，200 → 覆写
- 分片：`parts-<tag>.json` 记录 `{size, chunk, done: [...]}`，每片完成写一次；重开时跳过 `done` 里且片大小正确的

**字幕**：`/x/player/wbi/v2` 拿字幕列表，下载 JSON 后转 srt。时间戳用整数毫秒计算再取模，避免出现 `1000` 毫秒这种非法值。

**弹幕**：`/x/v1/dm/list.so?oid=` 拿 XML，转 ASS。按出现时间分轨（防重叠），颜色和字号可配。

### records.py（159 行）

**Records**：`{bvid}|{cid}|{ep_id}` → 下载完成信息的映射，存 `data/records.json`。

**Cache**：续传缓存。`dir_for(bvid, cid, ep_id)` 返回 `md5` 哈希路径（只算路径不建目录）；`drop(dir)` 递归删除并加路径保护（必须在该实例 `root` 下）。

清理策略：超过 7 天没动，或总量超过 4GB，自动清理最旧的。

### config.py（75 行）

配置项：下载目录、并发任务数、线程数、代理、Cookie、画质默认值、文件整理方式。存 `config.json`。

### 前端（web/）

**index.html**（302 行）：结构。顶栏状态、URL 输入、解析结果卡、任务列表、已下载面板、设置弹窗、登录弹窗。

**style.css**（931 行）：全部样式。深色底 + 单色强调。没有用任何 CSS 框架。

**app.js**（997 行）：全部逻辑。

- `renderParsed`：解析结果渲染，分组折叠
- `makeRow`：单条渲染，含"已下载"角标
- `buildJobCard` / `updateJobCard`：任务卡，`card._built` 保证 DOM 只建一次
- `buildJobActions`：按状态给不同按钮组（下载中给"取消"，失败给"重试"，中断给"继续下载"）
- 轮询 `/api/jobs` 每 0.8 秒刷新，只改变化的部分

**qrcode.min.js**：第三方二维码库，本地存放不走 CDN。

## 关键流程

### 一次下载的完整链路

```
1. 用户贴链接 → POST /api/parse
2. 后端识别类型 → 调对应解析函数 → 返回 parsed（含 items[]、总时长、预估体积）
3. 前端渲染列表，默认只勾未下载的
4. 用户勾选 → POST /api/jobs（带 parsed + options）
5. JobManager.create → 入队 → 后台线程 _run_job
6. _run_job 逐条调 _download_one
7. _download_one：
   a. 算 out_path → 存在则跳过
   b. 建缓存目录
   c. get_playinfo 拿流地址
   d. StreamFetcher 下视频流 / 音频流
   e. ffmpeg 合并
   f. 写附加文件
   g. records.mark + cache.drop
8. 收尾统计 done / cancelled / err → 判定任务最终状态 → 置 _dirty
9. 前端轮询看到 done，任务卡变绿
```

### 分片下载的线程模型

```
主线程
  ├── 切分 segments（按 chunk size）
  ├── 建 Queue，把所有 segment 塞进去
  ├── 起 N 个 worker（N = min(threads, len(segments))）
  │     └── 每个 worker：取 segment → Range 请求 → 写盘 → 标 done → 更新 manifest
  └── join 所有 worker
```

不是"一片一线程"，这是 v1.9 修掉的一个问题。

## 踩过的坑

### 1. 嵌入式 Python 缺标准库

华为云镜像的 `python-3.12.7-embed-amd64.zip` 带 `python312.zip`（3.6MB，599 个模块），可以直接用。

npmmirror 上有个同名包，**不含标准库**，解压后 import http.server 直接失败。选镜像时要确认包含 `python312.zip`。

### 2. ctypes 调系统对话框必须设 argtypes

```python
shell32.SHBrowseForFolderW.restype = ctypes.c_void_p
shell32.SHBrowseForFolderW.argtypes = [ctypes.POINTER(BROWSEINFOW)]
```

不设的话，64 位下返回值（指针）会被截断成 32 位，拿到的地址是垃圾，调用立刻崩。这是 Windows 上 ctypes 最常见的坑。

### 3. 中文文件名按字符截断会超限

Linux/Windows 文件名的 255 字节限制，中文 1 字 3 字节。按 84 个字符截断 = 252 字节，看起来没超，但加上扩展名和目录名就爆了。

改成字节级循环累加，压到 ≤200 字节。

### 4. HttpOnly Cookie 拿不到

`SESSDATA` 是 HttpOnly，JavaScript 读不到，程序也读不到浏览器 Cookie 库（加密存储）。所以"用浏览器登录后程序自动登录"这条路物理上不成立，只能扫码。

### 5. Range 请求的总长比 Content-Length 准

B 站 CDN 的 HEAD 响应经常给一个偏小的 `Content-Length`，导致进度条早早到 100% 又回退。

用 `Range: bytes=0-1` 请求，从响应头 `Content-Range: bytes 0-1/真实长度` 里读，这个值准。

### 6. 分片 manifest 的写盘时机

每片完成就写一次 manifest，而不是全部下完才写。否则进程被杀时 manifest 是空白的，续传等于没有。

代价是写盘频繁，但 manifest 只有几百字节，可以接受。

## 可复现的构建流程

```bash
# 1. 准备 Python 嵌入包
curl -L -o py.zip https://mirrors.huaweicloud.com/python/3.12.7/python-3.12.7-embed-amd64.zip
unzip py.zip -d runtime/python/

# 2. 准备 ffmpeg（imageio-ffmpeg 的静态版本）
pip download imageio-ffmpeg==0.8.1 --only-binary=:all: --platform win_amd64
# 解包取 ffmpeg.exe 到 runtime/

# 3. 同步源码
cp app.py biliapi.py downloader.py config.py records.py runtime/pkg/
cp web/* runtime/pkg/web/
cp 使用说明.txt runtime/pkg/

# 4. 打包
python -c "
import zipfile, os
with zipfile.ZipFile('BiliBox-win64.zip','w',zipfile.ZIP_DEFLATED,compresslevel=6) as z:
    for root, dirs, files in os.walk('runtime/pkg'):
        for f in files:
            if '__pycache__' in root or f.endswith('.pyc') or f == 'config.json':
                continue
            p = os.path.join(root, f)
            z.write(p, os.path.relpath(p, 'runtime/pkg'))
"
```

成品 47 文件 / 47.7MB，其中 ffmpeg.exe 101MB 压缩后占大头。
